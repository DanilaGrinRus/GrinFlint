# DEVICE_ACCEPTANCE — GrinFlint iOS (аппаратная приёмка RC)

Документ фиксирует **только те проверки, которые невозможны без физического
iPhone**. Всё остальное закрывается в CI и в этот список не входит.

Статус на 2026-10-29: **NOT VERIFIED** — устройство и подпись отсутствуют.
Пункты ниже ещё не выполнялись; строки «Ожидаемо» — это критерий приёмки,
а не заявление о результате.

## Поддерживаемые устройства и версии

- iPhone с Face ID или Touch ID, **iOS 17.0+** (deployment target проекта).
- Эталонное устройство для приёмки: iPhone 16 Pro (имя симулятора в CI;
  физический экземпляр — у владельца).
- Канал установки: бесплатный Apple ID (Personal Team) через Xcode на Mac
  владельца. CI готовит **неподписанный** Release archive + device
  XCFramework; подпись и установка выполняются локально (срок 7 дней,
  до 3 приложений).
- Сборка: Release, с настоящим FFI (`GRINFFI`), Share Extension включён.
  Для каждого прогона фиксируются: commit hash, номер CI-прогона, hash
  `.xcarchive`, версия Xcode/Rust.

## Сценарии

### D1. Вход по Face ID / Touch ID и отказ

- Предусловия: установлен RC; в iOS задан код-пароль и Face ID/Touch ID;
  в приложении включено «Требовать Face ID при входе».
- Действия: (1) свернуть и развернуть приложение — появляется замок;
  (2) отменить Face ID — экран остаётся закрытым, показана причина;
  (3) снова развернуть и успешно подтвердить — портфель открывается;
  (4) ввести код устройства вместо биометрии — открывается.
- Ожидаемо: без успешного подтверждения содержимое кошелька не показывается;
  отмена не снимает замок; текст ошибки понятен.
- Доказательства: запись экрана/скриншоты до и после, `lock.error`.
- Восстановление стенда: перезапуск приложения; при зависании — удалить и
  переустановить, кошелёк восстановить из seed.

### D2. Keychain: миграция и переживание обновления/перезагрузки

- Предусловия: сначала установлена **старая** сборка (до 2026-10-29) с
  незащищённым `wallet-password` и открытым кошельком; затем поверх
  устанавливается RC.
- Действия: (1) открыть RC — при первом чтении пароля ожидается запрос
  Face ID и перенос записи; (2) настройки → диагностика Keychain;
  (3) перезагрузить iPhone, открыть приложение; (4) обновить приложение
  повторно.
- Ожидаемо: «пароль перенесён под защиту Face ID»; после перезагрузки и
  обновления кошелёк открывается, баланс и история на месте; второй
  параллельной записи-пароля нет.
- Доказательства: скриншот диагностики, журнал операций, баланс до/после.
- Восстановление: не удалять приложение до подтверждения переноса; при
  сбое — сохранить seed заранее (он не зависит от Keychain).

### D3. Системные прерывания и переключатель приложений

- Предусловия: открыт экран отправки с введёнными данными; включена
  автоблокировка.
- Действия: (1) входящий звонок/Siri во время запроса Face ID;
  (2) уход в фон и возврат; (3) двойной клик — snapshot в переключателе.
- Ожидаемо: после возврата — замок; в snapshot нет seed-фразы, адресов и
  сумм; незавершённая операция не теряется и продолжается после входа.
- Доказательства: фото переключателя, повторный вход, карточка «Незавершённый
  перевод» с прежним этапом.

### D4. Камера и QR

- Предусловия: приложение без разрешения камеры; затем разрешение выдано.
- Действия: (1) отсканировать QR адреса при слабом освещении; (2) отменить
  системный запрос доступа; (3) поднести QR ответного Slatepack.
- Ожидаемо: при отказе — понятное сообщение и ручной ввод; при разрешении
  адрес/Slatepack подставляются, денежное действие не выполняется без
  подтверждения.
- Доказательства: скриншоты, содержимое поля после скана.

### D5. Share Extension из сторонних приложений

- Предусловия: RC установлен; в Safari/Telegram/Заметках есть текст
  Slatepack.
- Действия: «Поделиться» → GrinFlint; проверить также файл и ссылку
  `grinslate://…`.
- Ожидаемо: открывается лист приёма с подставленным текстом; при
  повреждённых данных — ошибка без автоматического приёма средств.
- Доказательства: скриншот листа, запись экрана.

### D6. Сеть: мобильная сеть и LAN-нода

- Предусловия: своя testnet-нода в локальной сети; мобильный интернет.
- Действия: (1) указать `127.0.0.1:13413` — должен быть отказ с
  объяснением; (2) указать LAN-адрес ноды — проверка доступности и
  genesis-совместимости; (3) переключиться с Wi-Fi на LTE во время
  обновления; (4) выключить сеть.
- Ожидаемо: локальный адрес отклоняется на устройстве; своя нода
  подключается; при обрыве — «баланс неизвестен/устарел», а не нули;
  после восстановления связи обновление продолжается.
- Доказательства: скриншоты проверки ноды и состояний баланса.

### D7. Реальные экраны, доступность, ресурсы

- Действия: Dynamic Type (макс.), VoiceOver по портфелю/отправке/приёму,
  20 минут работы с обновлением баланса, фоновая музыка/звонок.
- Ожидаемо: текст не обрезается, кнопки доступны VoiceOver, нет заметного
  нагрева/падения батареи, приложение не убивается системой во время
  отправки.
- Доказательства: скриншоты, показания батареи/температуры.

## Порядок приёмки

1. Собрать и подписать RC на Mac владельца (Personal Team), установить.
2. Пройти D1–D7 по порядку, фиксируя hash сборки и доказательства.
3. Для каждого пункта — PASS/FAIL/NOT VERIFIED; FAIL блокирует RC.
4. После приёмки — восстановить стенд: удалить приложение, переустановить
   свежий RC, кошелёк восстановить из seed и сверить адрес/баланс.

## Что не входит

- Внешний аудит крипто-кода (исключён из объёма задачи).
- Встроенная нода, Nostr/Tor-автоматизация, multiwallet, публикация в
  App Store.
